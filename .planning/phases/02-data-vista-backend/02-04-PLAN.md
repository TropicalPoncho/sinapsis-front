**`export async function GET()`** hace exactamente dos consultas, en paralelo con `Promise.all`,
literalmente estas y sin `JOIN` ni subconsultas:

```sql
SELECT id, node_type, label, descripcion_breve, thumb, viz_params,
       is_stub, fecha, disciplina, location_id
FROM nodos
```
```sql
SELECT id, origen, destino, tipo_vinculo, rol
FROM vinculos
```

`metadata` queda afuera del primer SELECT por DATA-02 y `descripcion` afuera del segundo por
DATA-04: son la data profunda, se piden al abrir el nodo o el vínculo. Dejar el porqué como
comentario arriba de cada consulta.

**Mapeo de fila a contrato** (snake_case de la base → camelCase de `vista.ts`), campo por campo:
- `id` → `id`
- `node_type` → `nodeType`

- `descripcion_breve` → `descripcionBreve`, **omitido** si es `null` (el contrato lo declara opcional)
- `thumb` → `thumb`, omitido si es `null`
- `viz_params` → `vizParams` (`pg` ya devuelve `jsonb` parseado como objeto)

```typescript
import { construirAdyacencia } from './adyacencia'
import type { Adyacencia } from './adyacencia'
import type { Subgrafo } from '@/types/vista'

let pendiente: Promise<Adyacencia> | undefined

export function cargarAdyacencia(): Promise<Adyacencia>

/** Solo para tests y para el reset entre navegaciones duras. */
export function olvidarTopologia(): void
```

Comportamiento exacto:
- `cargarAdyacencia()` memoiza la **promesa**, no el resultado: si se llama dos veces antes de que
  la primera resuelva, sigue habiendo un solo `fetch`. Es la diferencia entre memoizar la promesa y
  memoizar el valor, y es lo que hace verdadera la frase "el cliente pide la topología una vez".
- El fetch es `fetch('/api/topologia')`. Si `!res.ok`, limpiar `pendiente` (para que un reintento
  sea posible) y lanzar `new Error(\`topología: HTTP ${res.status}\`)`.
- El JSON se pasa tal cual a `construirAdyacencia`, que ya descarta aristas colgantes.
- `olvidarTopologia()` pone `pendiente = undefined`.

Import de `./adyacencia` **sin extensión** acá: este módulo lo empaqueta Next, no lo ejecuta `node`
pelado, y el bundler resuelve sin extensión igual que el resto del repo. (El archivo de test del
plan 02-02 sí usa `./adyacencia.ts` porque lo carga el resolver de ESM de Node.)

Encabezado:
```typescript
// VIST-04: la topología se pide una sola vez y todas las Vistas se resuelven sobre este índice.

```

Este plan no monta ningún componente ni ninguna página: la UI es la fase 4. Lo que tiene que quedar
