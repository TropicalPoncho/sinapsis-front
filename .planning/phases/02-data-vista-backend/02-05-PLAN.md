```sql
nodos (id, node_type, label, descripcion_breve, thumb, viz_params,
       is_stub, fecha, disciplina, location_id, metadata)

vinculos (id, origen, destino, tipo_vinculo, rol, descripcion)

  FOREIGN KEY destino REFERENCES nodos(id) ON DELETE CASCADE

  CHECK rol IS NULL OR length(rol) <= 60
  CHECK origen <> destino
  UNIQUE NULLS NOT DISTINCT (origen, destino, tipo_vinculo, rol)
```

**Validación antes de escribir nada** — recorrer todas las filas, juntar todos los errores y, si hay

**Mapeo de cada nodo:**
- `id` ← columna `id` (el ObjectId de Mongo). Reusarlo es lo que hace la importación re-corrible y
  mantiene la llave de join con la planilla.
- `node_type`, `label`, `disciplina` ← las columnas homónimas; vacío → `NULL`.
- `descripcion_breve` ← columna homónima; vacío → `NULL`. **Nunca** se copia `info.bio` acá: la bio
  larga va a `metadata`, así que el tope de 200 de DATA-08 no obliga a truncar prosa. Si aun así una

- `is_stub` ← `si` → `true`, cualquier otra cosa → `false`.
- `fecha` ← columna homónima (`YYYY-MM-DD`) → `timestamptz`; vacío → `NULL`.
- `thumb` ← columna homónima, **pero**: si el valor empieza con `REVISAR:` va `NULL` y se loguea
  `thumb sin resolver: <label>`. Los assets viven en `collectiveConscience`, que es solo lectura, y
  todavía no hay una URL pública decidida. Dejar acá:
  ```typescript
  // ponytail: thumb queda en NULL mientras el prefijo REVISAR: siga puesto. Los archivos están en
  // collectiveConscience (solo lectura). Se resuelve cuando se decida dónde se sirven los assets
  // — en la fase 4 o 5, editando la columna thumb del CSV.
  ```
- `viz_params` ← **asignado, no migrado** (D-10: el dump no tiene estilos que traducir). Tabla por
  `node_type`, con estos valores exactos:

  | node_type | shape       | color     |
  |-----------|-------------|-----------|
  | ARTISTA   | `Marble`    | `#6EE7B7` |
  | OBRA      | `Perlin`    | `#F472B6` |
  | SERIE     | `Twist`     | `#FBBF24` |
  | ESPACIO   | `Fire`      | `#60A5FA` |
  | EVENTO    | `Wave Line` | `#A78BFA` |
  | STUB      | `Lines`     | `#6B7280` |

  Más `speed: 1`, `noise: 0.5` y `seed` **derivada del id de forma determinista** — no
  `Math.random()`: la seed tiene que ser estable entre corridas para que reimportar no reacomode la
  animación de toda la red, y `Math.random()` haría que dos corridas dieran bases distintas. Usar un
  hash simple del id (p. ej. FNV-1a de 32 bits) normalizado a `[0, 1)` con tres decimales.
  El objeto queda `{ shape, color, speed: 1, noise: 0.5, seed }` — cinco escalares, ni uno anidado.
  Si alguna vez alguien mete un objeto o un string largo ahí, la CHECK `viz_params_escalares` de la

**Mapeo de cada vínculo:** `id`, `origen`, `destino`, `tipo_vinculo` ← columnas homónimas;
`rol` vacío → `NULL`; `descripcion` siempre `NULL` (no hay nada equivalente en la data vieja, y es
lo que se carga después a mano).

**Escritura**, en una sola transacción:
```sql
BEGIN;
TRUNCATE vinculos, nodos RESTART IDENTITY CASCADE;
-- INSERT INTO nodos (...)    -- uno por fila, con parámetros $1..$11
-- INSERT INTO vinculos (...) -- uno por fila, con parámetros $1..$6
COMMIT;
```
`TRUNCATE` primero es lo que hace la importación repetible: correrla dos veces deja la base igual.
Nodos antes que vínculos, por las foreign keys. **Siempre** consultas parametrizadas (`$1`, `$2`,
…), nunca concatenando strings: los labels traen comillas y acentos.

Al terminar, imprimir el resumen:
```
nodos importados:    N (descartados: M)
vinculos importados: N (descartados: M)
thumbs sin resolver: N
```
