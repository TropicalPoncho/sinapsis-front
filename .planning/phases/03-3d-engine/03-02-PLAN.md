<interfaces>
Lo que el motor recibe (`src/types/vista.ts`, no redeclarar):
```ts
interface NodoGrafo { id: string; nodeType: NodeType; subtipo: string; label: string;
  descripcionBreve?: string; thumb?: string; vizParams: VizParams; isStub: boolean;
  fecha?: string; disciplina?: string; locationId?: string }
interface VizParams { shape: string; color: string; speed?: number; noise?: number; seed?: number }
interface VinculoGrafo { id: string; origen: string; destino: string; tipoVinculo: TipoVinculo; rol?: string }
interface Subgrafo { nodos: NodoGrafo[]; vinculos: VinculoGrafo[] }
```

Lo que consume el registry de ThreeObjects (leído de las clases, no inventado):
- `ThreeObjectManager.createObject(node)` usa `node.type`; si el tipo no está registrado **tira**.
- `ThreeObject` copia sobre la instancia toda clave homónima de `node`: `speed`, `size`.
- `crossedLinesThreeObject`, `linesThreeObject`, `simpleTextThreeObject` leen `node.color`.
- `simpleTextThreeObject` y las labels leen `node.name`.
- `imageThreeObject` lee `node.img`, `node.nodeSize`, `node.imgSize`.
- Los 15 tipos registrados por `registerTypes.js`: `CrossedLines`, `Fire`, `Image`, `Lights`,
  `Lines`, `SinLink`, `Marble`, `Noise`, `Particles`, `Perlin Noise`, `Perlin`, `SimpleText`,
  `Text`, `Twist`, `Wave Line`. El default es `Lines` (`ThreeObjectManager.defaultType`).

Lo que consume `3d-force-graph`: `{ nodes: [{ id, ... }], links: [{ source, target, ... }] }`.
</interfaces>

  <behavior>
    - `disposeUnusedObjects(['a'])` con instancias `a` y `b` deja `_objectInstances` con sólo `a`.
    - La geometría de `b`, si **no** está en `ThreeObject.geometryCache`, recibe `dispose()`.
    - La geometría de `b`, si **sí** está en `ThreeObject.geometryCache`, **no** recibe
      `dispose()` — porque `a` la sigue usando.
    - Los materiales y las texturas de `b` reciben `dispose()` en los dos casos (son por instancia).
    - `disposeUnusedObjects([])` vacía todo y sigue sin disponer geometrías compartidas.
    - Un mesh con hijos: los hijos se recorren y sus materiales se disponen.
  </behavior>

  <action>
    1. En `_disposeMesh`, reemplazar `if (mesh.geometry) { mesh.geometry.dispose(); }` por una
       guarda que salte las geometrías compartidas:

    ```js
    // El geometryCache es estático y compartido entre instancias: disponer acá la geometría de
    // un nodo que sale de escena rompería a todos los que quedan usando la misma clave.
    // Materiales y texturas sí son por instancia y se disponen siempre.
    // ponytail: el cache no se libera nunca — son ~15 geometrías, techo constante. Si algún día
    // las claves dependen de datos del nodo (tamaño por nodo), acá va un refcount.
    if (mesh.geometry && !ThreeObjectManager._esGeometriaCompartida(mesh.geometry)) {
        mesh.geometry.dispose();
    }
    ```
       y un helper estático:
    ```js
    static _esGeometriaCompartida(geometry) {
        for (const g of ThreeObject.geometryCache.values()) if (g === geometry) return true;
        return false;
    }
    ```
       `ThreeObject` ya está importado en el archivo — no agregar imports.

    2. Cambiar los dos `console.log` de `disposeUnusedObjects`/`disposeAll` por nada, o dejarlos
       detrás de una guarda de desarrollo. Con transiciones por cada navegación esos logs corren
