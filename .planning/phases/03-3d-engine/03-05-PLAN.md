<interfaces>
De `src/engine/graph/encuadre.js` (Plan 01, puro y testeado — se consume, no se re-deriva):
```js
centroAreaSegura(areaSegura, W, H) -> {x, y}
offsetDeAreaSegura(areaSegura, W, H) -> {x, y}          // para camera.setViewOffset
distanciaParaEncuadrar(radio, rectW, rectH, canvasH, fovGrados, margen=0.9) -> number
centroide(nodos, idExcluido) -> {x,y,z} | null
ladoDestino(areaSegura, W, H) -> {x, y}
posicionCamaraParaFoco(nodo, signo, distancia, azimut) -> { pos, lookAt }
elegirLadoOrbit(nodoEnfocado, nodos, areaSegura, W, H, distancia, azimut) -> 1 | -1
```

Del contrato: `AreaSegura { top, right, bottom, left }` son **insets desde cada borde**
(convención CSS `inset`), no coordenadas absolutas. Escritorio: el panel tapa el 62% izquierdo →
`left = 0.62 * W`. Mobile: la banda libre es la superior → `bottom = 0.6 * H`.

De `3d-force-graph` (verificado contra el source instalado):
- `graph.camera()` → la `PerspectiveCamera` viva. **Accesor, no propiedad.**
- `graph.cameraPosition(pos, lookAt, ms)` → encadenable, **sin `onComplete`**. El tween interno
  termina exactamente en `ms`: `setTimeout(resolve, ms)` no es una aproximación.
- `graph.graph2ScreenCoords(x, y, z)` → `{x, y}` en píxeles del canvas. Proyecta por la misma
  cámara, así que ya contempla el `setViewOffset` activo. No hacer `Vector3.project` a mano.
- `PerspectiveCamera.setViewOffset(W, H, offsetX, offsetY, W, H)` llama
  `updateProjectionMatrix()` internamente y **no** rompe el picking: `three-render-objects`
  raycastea por la misma matriz.
</interfaces>
