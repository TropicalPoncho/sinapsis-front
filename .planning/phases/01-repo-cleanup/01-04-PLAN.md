  <action>
Create `C:/Users/ramac/source/TropicalPoncho/sinapsis/sinapsis_front/docker-compose.yml` with
exactly this content:

```yaml
services:
  db:
    image: postgres:16-alpine
    restart: unless-stopped
    environment:
      POSTGRES_USER: strapi
      POSTGRES_PASSWORD: strapi
      POSTGRES_DB: strapi
    ports:
      - "5432:5432"
    volumes:
      - sinapsis_pgdata:/var/lib/postgresql/data
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U strapi"]
      interval: 5s
      timeout: 5s
      retries: 5

volumes:
  sinapsis_pgdata:
```

Notes on each choice, so none of them get "improved":

- **No top-level `version:` key.** The local Docker Compose is the V2 plugin (`docker compose`, no
  hyphen). V2 treats `version:` as obsolete and prints a warning.
- **`postgres:16-alpine`** — current, small, broadly compatible. No official Strapi 5 Postgres
  compatibility matrix exists; 16 is a safe default and DATA-01's schema is Phase 2's problem.
- **Named volume, not a bind mount.** A relative bind mount on Windows produces permission grief for
  the Postgres data directory.
- **`db` service only.** Strapi runs on the host via `npm run develop`. Do not add a `strapi`
  service, an `adminer`, a `pgadmin`, or a network block.
- **Credentials are `strapi`/`strapi`/`strapi` for local dev.** These are not secrets and they are
  what Task 2's scaffold flags point at. Do not parameterise them through a root `.env` — there is
  one developer and one machine.

Then bring it up and prove it accepts connections. Run from the repo root:

```bash
docker compose up -d db
docker compose exec -T db pg_isready -U strapi
```

Docker Desktop must be running. If `docker compose up` fails because the daemon is not running,
stop and report — do not fall back to a host-installed Postgres or to SQLite.

Root `.gitignore` already has `/node_modules` (root-anchored) and `.env*`. Do not edit it in this
task; Task 2 handles the `strapi/node_modules` question.
  </action>

**After the scaffold, three cleanups — all deterministic, regardless of which flag names existed:**

1. **No nested git repository.** If `strapi/.git` exists, delete it:

   `strapi/.gitignore` covering it. Check:

   If that prints anything, append `node_modules/` to `strapi/.gitignore` (creating the file if the
   scaffold did not) and re-check until it prints nothing. Do not edit the root `.gitignore`.

3. **No workspace hoisting.** Confirm `strapi/node_modules` exists as a real directory and that the
   root `package.json` still has no `workspaces` key. Two independent apps, two dependency trees.
